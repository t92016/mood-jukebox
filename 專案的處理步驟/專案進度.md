排查「點歌/聊天偶發卡住」問題，確認模型與 API Key 都正常，完成四項韌性修復：

### 🔍 診斷結論（實測驗證）
- 模型 `qwen/qwen3.8-27b` 存在且正常、Vercel 上的 GROQ_API_KEY 有效、mood/chat 兩種模式單次測試都通過
- 真正原因：**Groq 免費層間歇性錯誤（429 速率限制 / 503 過載）** + 前後端都沒有對 HTTP 錯誤重試 → 失敗時畫面停在原處，看起來像卡死
- 此 Key 限制：8000 tokens／約 3 分鐘窗口（單人測試不會爆，全班同時點歌才可能撞牆；若未來要全班同用，再評估付費層）

### ✅ 修復一：後端 HTTP 錯誤納入重試（api/recommend.js）
- 重構出 `callGroq` / `extractRec` / `callGroqWithRetry` 共用函式
- 最多重試 3 次、遞增等待（0.6s → 1.2s），HTTP 錯誤、網路錯誤、JSON 解析失敗全部覆蓋
- 依最後錯誤類型回傳對應訊息（HTTP 錯誤 →「AI 服務暫時休息中」；解析失敗 →「點唱機打盹了」）

### ✅ 修復二：前端失敗顯示「🔄 再試一次」按鈕
- 聊天模式：失敗時在對話區顯示虛線重試氣泡，按鈕點下直接重送（chatHistory 已含使用者訊息，不會重複）
- 點歌模式：狀態列附「🔄 再試一次」按鈕（index.html 新增 statusRetryBtn），一鍵重發同一個心情

### ✅ 修復三：聊天中重新點歌不再疊畫面

## 重大技術決策
| 決策 | 理由 |
|---|---|
| 用 Vercel Functions 而非純前端 | 規劃書缺後端；Groq Key 放前端會被秒偷，必須代理 |
| 用 Vercel 而非 GitHub Pages / Netlify | Pages 純靜態跑不了 Functions；Vercel 免費額度足夠且連 repo 自動部署；Netlify 帳號被封 |
| Netlify → Vercel 遷移 | 新舊 Netlify 帳號均被封鎖，Vercel 提供同等功能（Serverless Functions + 環境變數 + Git 自動部署） |
| GitHub repo 設 private | Netlify 免費版支援 private repo，兒童專案保守為上（develop skill 的 public 慣例是為了 Pages，本案不適用） |
| `Users` 集合改名 `MoodLogs` | 無帳號系統，匿名日誌用 MoodLogs 名實相符 |
| Firestore 前端直連（不經代理） | Firebase client SDK + Security Rules 本來就設計給前端用；多一層代理只增延遲 |
| Firebase 未設定時優雅降級 | `firebase-config.js` 沒填也能點歌（不寫紀錄），方便先測 UI |
| 種子歌放 `seeds/songs-seed.json` 不寫死 videoId | videoId 由 seed 腳本實際呼叫 API 取得，不假造 |
